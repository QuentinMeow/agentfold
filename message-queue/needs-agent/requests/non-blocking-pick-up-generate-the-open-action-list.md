## What you need to know

Every pending action already has exactly one file and a filename that says when unresolved
work stops. Nothing aggregates them, so the complete picture exists only inside a chat
reply an agent happened to write.

The digest is a projection, not a source. It restates nothing a queue item does not already
carry, and it links every bullet back to the file that owns the fact. Generate it the way
`memory/index.md` is generated — one regeneration mode on the reconciler, one check that
refuses a commit when the tracked bytes stop matching their inputs.

One constraint is easy to miss: the generated bytes may not depend on today's date. A digest
that renders lateness would make an untouched clean tree start failing the morning a
deadline passed. Lateness already belongs to the advisory `stale-queue` check.
