# Two of the nine constitution files quote numbers that have since changed — may an agent fix them?

**Action:** Choose whether an agent corrects the stale numbers in two principle files now, leaves them alone, or gets a standing permission to correct facts of this kind without asking.
**Why this matters:** The nine principle files are the most-quoted documents here, and one of them tells agents a size limit smaller than the real one, so an agent will cut a contract that was never too long.
**If you do nothing:** Nothing stops. The two files keep quoting numbers that are no longer true, and every agent that reads them inherits the wrong ones.

## What you need to know

**Today:** the root contract file is 136 lines. The check that runs before every commit allows 140 and is the only place that limit lives. The progressive-disclosure principle says the root contract "fits in ~130 lines", which was true when written. The forgetting principle has the same shape of error: it gives memory entries a review date "default 90 days", while the templates that set those defaults use 90 for two kinds of entry and 180 for the other two.

**What this would change:** two clauses, from copied numbers to a pointer at whatever owns them. No rule in either file changes.

**What this does not decide:** the other principle question already waiting on you, about whether the eventual-consistency file may stop claiming repair items are filed automatically. That one changes what its principle promises; these two only delete borrowed numbers.

This is a question at all because two contracts say an agent may not edit a principle without your approval, and neither excuses small or factual changes.

## Your choices

The choices differ in how much of this class you settle now, rather than in what the two files end up saying.

### Option A — Fix these two clauses
Each number is replaced by a pointer to the file that owns it. Costs your approval and a short record explaining why an edit to the constitution was allowed.
*Example consequence:* the next agent that reads the progressive-disclosure principle is told to keep contracts inside the checked budget rather than under 130 lines, and stops trimming a file that was already short enough.

### Option B — Leave both as written
No edit, no record.
*Example consequence:* an agent adds four needed lines to the root contract, sees 140 in the check and ~130 in the principle, and either deletes something useful or files a question asking which number wins.

### Option C — Fix them, and give a standing permission for this class
Same edits, plus a recorded rule: an agent may correct a principle when the correction only removes a duplicated fact that another file owns, and no rule in the principle changes. Anything that alters what a principle claims still comes to you.
*Example consequence:* the third case of this — and there will be one, because two surfaced in a single audit — is fixed in the same commit that finds it, and you are never asked about a copied number again.

## What I recommend

**Recommendation:** Option C — the two instances found today were found by one audit of one afternoon, so the class is real, and answering it once costs you less than being asked each time.
**Strongest case against this:** "no rule changes" is the agent's own reading of its own edit, and no check can test it; a standing permission is only as narrow as the next agent's judgment. If you want the constitution to stay something agents cannot touch alone, A fixes today's problem without widening the door.
