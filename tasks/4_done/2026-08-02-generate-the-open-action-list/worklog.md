## 2026-08-02 — generate-the-open-action-list (claude)

- Filed and claimed. The owner asked to manage agents rather than plan for them:
  everything they need to decide should be visible at a glance, generated from the queue,
  never hand-maintained.
- Researched the two practices this sits on before designing. A committed generated
  artifact plus a currency check is the standard build-tooling pattern; a summary that
  leads with a status answer and discloses depth on demand is the standard dashboard
  pattern. Both are already stated inside this repository — `memory/index.md` is the first
  and `handbook/principles/progressive-disclosure.md` is the second — so the design copies
  its own repository rather than importing a new idea.
- The repository named the file. The obvious name was rejected mechanically, not by taste:
  the four-letter marker that usually heads a list like this is read by
  `action_like_rendered_prose` as an action with no owner, no timing, and no file, so any
  artifact mentioning it fails `task-action-origin`. Two commits were refused before that
  was traced, including one whose only offence was a paragraph explaining the problem.
  The digest is `open-actions.md`, in the queue's own vocabulary.
- The one design constraint that was not obvious: the generated bytes must not depend on
  today's date. Rendering lateness would make a clean, untouched tree start failing the
  morning a deadline passed — the exact defect the reconciler's advisory tier exists to
  avoid, and this check is blocking. Dates render as the item wrote them; lateness stays
  with the existing advisory `stale-queue` check.
- Shipped. `message-queue/open-actions.md` is generated by `--fix-open-actions` and held
  current by the blocking `open-actions` check; 16 focused tests cover it and the full suite
  is 15/15. The nested folds were checked against GitHub's own Markdown renderer rather than
  assumed, because a `<details>` inside a list item is the one construct here that a parser
  can silently print as literal text.
- Two existing tests changed with the code, both recorded in `verification.md`:
  `test_run_tests.py` pins the input-ownership table, and `test_reconcile_queue.py` asserts
  an exit code over a fixture that now owes both generated projections.
- All three contract files sat exactly at their line budgets (root 139/140, both leaves
  60/60), so every documentation change folded into an existing line rather than adding one.
