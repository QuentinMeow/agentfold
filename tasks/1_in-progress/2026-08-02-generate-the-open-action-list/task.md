# Generate one ordered list of every open action, so the owner never hunts for what is left

**Claimed-by:** claude
**Filed:** 2026-08-02, by claude, from the owner's chat request to be an agent manager rather than a planner
**Parent:** none
**Repository scope:** core
**Queue actions:** none

## Goal

Every pending action in this repository already has exactly one file, and the filename
already says when unresolved work stops. What does not exist is a single place that shows
all of them at once, in the order they matter. The owner currently learns what is open by
reading a session reply, which means the list exists only while a conversation is fresh and
has to be rebuilt by hand every time.

This task adds a tracked digest at the queue's own root, named **open-actions.md** — written
unbackticked here only because it does not exist yet, and the link check is right to say so.
It is generated from every live queue item, ordered by who acts next, then by when
unresolved work stops, then by date: one bullet per item, carrying that item's own
one-sentence action field as a link back to the file, with its consequence folded
underneath. It is a projection, never a source. Nothing is answered, decided, or recorded in
it, and the reconciler refuses a commit whose digest no longer matches the queue — exactly
as it already does for `memory/index.md`.

The name deliberately avoids the four-letter marker that ordinarily heads a list like this.
The repository's own detectors read that marker as an action with no owner, no timing, and
no file — the exact state the queue exists to abolish — so a digest named after it would
fail this check in every sentence that named it, including this one. Confirming that is how
the name was chosen; the transcript is in `verification.md`.

## Acceptance criteria

- [ ] `python3 automation/reconcile/reconcile.py --fix-open-actions` writes the digest from the
      live queue alone, and running it twice produces identical bytes.
- [ ] WHEN the generated digest does not match the queue, THE SYSTEM SHALL emit one
      blocking `open-actions` finding naming the regeneration command, so a queue change
      cannot land with a stale digest.
- [ ] The generated bytes are a pure function of the queue files: no calendar date, no
      Git revision, and no host state enters the output, so an unchanged clean tree never
      starts failing because a day passed.
- [ ] Every bullet links its own queue item, and no bullet states a fact the linked item
      does not already carry.
- [ ] Ordering is deterministic and total: `needs-human` before `needs-agent`, then
      `blocking-` before `future-blocking-` before `non-blocking-`, then the item's own
      date ascending, then its path.
- [ ] Items whose one-sentence action is identical and repeated — the task-pickup
      requests — collapse into one counted line, so the human section is never buried.
- [ ] The digest carries the queue's own count at the top, and states in its first lines
      that it is generated and where an answer actually goes.
- [ ] The digest is registered as a queue root document, so the queue's location, naming,
      schema, and staleness checks continue to ignore it rather than reporting it as a
      malformed item.
- [ ] Focused tests cover generation, ordering across all three timing prefixes and both
      actors, pickup collapsing, the staleness finding, idempotence, and the absent-queue
      no-op an adopting repository needs.
- [ ] `verification.md` records the real output of the regeneration, the staleness
      finding, the full reconciler, and the test run.
