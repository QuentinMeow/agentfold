# Let a human answer a queue item in one edit, and make every queue template copy-valid

**Claimed-by:** unclaimed
**Filed:** 2026-07-31, by claude, from chat
**Parent:** none
**Repository scope:** core
**Queue actions:** `message-queue/needs-agent/requests/non-blocking-pick-up-let-a-human-answer-in-one-edit.md`

## Goal

The one interaction this whole repository exists to serve — a human answering a queued
action — fails closed the first time it is tried. Root `AGENTS.md` describes committing
the response while the item is `waiting`, but a review answered that way is rejected by
`queue-schema`: acceptance also depends on hand-written `Reviewed revision` and
`Review outcome` values, and nothing visible in the filed item mentions them. A
backticked path in the same answer adds a third rejection from `link-check`. Every
repair path is then contract-forbidden, since the first human response is immutable and
human text is not agent-editable.

Underneath that sits a second failure: no template in `templates/queue/` is
copy-and-fill valid. `fields()` runs `semantic_text()` first, which blanks HTML
comments, and every timing field (`Blocks now`, `Blocks at`, `Until then`,
`If unanswered`) exists in the templates only inside `<!-- ... -->`. Copying a template
and filling it in guarantees a `queue-schema` failure, which contradicts
`templates/README.md`'s single-source-of-truth claim.

This task moves `Reviewed revision` and `Review outcome` from the human's commit to the
agent's `folding` claim without weakening what they buy, makes every queue template
copy-and-fill valid, and documents the schema fields that code requires but no template
shows.

## Acceptance criteria

- [ ] A human can answer any live `needs-human` item by typing one sentence after
      `**Your answer:**` or `**Your review:**` and committing, with no other edit, and
      `python3 automation/reconcile/reconcile.py --check` reports 0 blocking findings
- [ ] A backticked path inside a human response never produces a `link-check` finding,
      whether or not that path exists
- [ ] A review still cannot resolve without being bound to the exact revision it judged
      and carrying a terminal `Review outcome`; both are required at `folding` and at
      deletion
- [ ] The agent's terminal binding is write-once, may only be recorded on the
      `waiting` -> `folding` claim edge, and may only follow a human response that was
      already committed in the parent commit
- [ ] Every file in `templates/queue/` can be copied, filled in by substituting its
      visible placeholders, and committed with 0 blocking findings — proven per template
- [ ] The schema fields required by code with no template (`Task admission schema`,
      `Queue resolution schema`, `Queue projection schema`, `Queue action-entry schema`,
      `Queue liveness schema`, `Collaboration mode`, `Last-updated`) and the
      reconciler-only retry fields (`Generated by`, `Finding identity`) are documented
      once, without restating any schema twice
- [ ] Regression tests cover all three defects, including a copy-and-fill test that
      iterates every queue template
- [ ] `python3 automation/reconcile/reconcile.py --check` exits 0 and
      `python3 automation/run_tests.py` passes, with real output in `verification.md`
