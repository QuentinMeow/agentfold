# docs/ — durable engineering proposals

This service owns technical designs and the research that supports them. It explains
possible futures; `handbook/` owns current operating principles, `memory/decisions/`
owns accepted decisions, and `tasks/` owns implementation state.

## Routes

| Path | Enter when |
|------|------------|
| `designs/` | comparing approaches or designing a system before implementation |

Design documents are explanations, not workflow records, so they intentionally have no
mandatory template. Prefer primary sources, label inferences as such, and link rather
than restating current contracts. Before editing a design, read `designs/AGENTS.md`.
