## What happened

- **Added `message-queue/open-actions.md`**, one generated list of every live queue item.
  It orders them by who acts next, then by the filename's timing class, then by the item's
  own date. Each bullet is that item's own `Action` sentence, linked back to it, with the
  consequence folded underneath; the twenty-five repeated task-pickup requests collapse
  into one counted line so they cannot bury the owner's own questions.
- **It is a projection, and the reconciler keeps it one.** `--fix-open-actions` writes it,
  and the blocking `open-actions` check refuses any commit whose digest stopped matching
  the queue — the same contract `memory/index.md` has had since adoption. No line in it
  states a fact its linked item does not already carry.
- **The generated bytes do not depend on today**, and that is what makes a blocking check
  safe here. Rendering lateness would make an untouched clean tree start failing the
  morning a deadline passed. Dates render exactly as the item wrote them; lateness stays
  with the advisory `stale-queue` check, which is advisory for that reason.
- **The repository chose the file's name.** The obvious one was rejected mechanically: the
  four-letter marker that usually heads a list like this is read by
  `action_like_rendered_prose` as an action with no owner, no timing, and no file, so any
  artifact naming it fails `task-action-origin`. Two commits were refused before that was
  traced, one of them a paragraph whose only offence was explaining the problem.
- **Sixteen focused tests, full suite 15/15, reconciler 0 blocking.** The nested `<details>`
  inside a list item was checked against GitHub's own Markdown renderer rather than
  assumed, because that is the one construct here a parser can silently print as text.

## How it works now

Open `message-queue/open-actions.md` and the first two lines say whether anything is
stopping work and how many questions are yours. Every bullet is one sentence; the reasoning
is behind a disclosure triangle. Answering still happens in the linked file and nowhere
else, which the file says in its own third line. Any commit that changes the queue without
regenerating the digest is refused with the command that fixes it.

## Decisions made for you

- **The digest is tracked, not generated on demand.** An adopted repository's first commit
  after taking `message-queue/` will fail until it runs `--fix-open-actions` once, which is
  the same cost `memory/index.md` already imposes. Undoing this means deleting one file and
  one `CHECKS` entry; leaving it is what makes the list readable on a phone without a
  checkout. Reasoning and the two rejected alternatives are in the task's `design.md`.
- **Lateness is not rendered.** The list shows `answer by 2026-10-31` and never "overdue",
  because computed urgency would put today's date into tracked bytes. This is the one
  capability a reader might expect and not find; `stale-queue` already reports it.
- Nothing else. No queue item was answered, resolved, deleted, or reworded, and no human
  answer was interpreted.
